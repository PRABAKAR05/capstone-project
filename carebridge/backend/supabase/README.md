# CareBridge AI — Database, Migrations & RLS Architecture

**PostgreSQL / Supabase Schema, Row Level Security (RLS) & Migration Suite**

This directory contains the database migration scripts, Row Level Security policies, cryptographic triggers, seed data scripts, and recovery procedures for the CareBridge AI platform.

---

## Architectural Principles

1. **Defense-in-Depth via Row Level Security (RLS):**
   Every clinical table has RLS enabled with explicit tenant isolation policies (`hospital_id = current_setting('app.current_hospital_id', true)` or linked patient profiles).
2. **Reversible Migrations:**
   Every schema migration (`000X_*_schema.sql`) has a matching rollback script (`000X_*_down.sql`).
3. **Dual-Context HMAC Administrative Corrections:**
   `0008_phase15_retire_roles.sql` implements a zero-trust administrative correction procedure. Table mutations to protected fields require both an authorized session context and a valid HMAC-SHA256 signature generated by an out-of-band DBA key.
4. **Referential Integrity & Safe Deletions:**
   Critical clinical relationships use `ON DELETE RESTRICT` to ensure patient histories, prescriptions, and audit events cannot be accidentally orphaned or purged.

## Utility & Verification Scripts

- **`apply_migration.py`:** Applies pending SQL migrations against the target Supabase / PostgreSQL database.
- **`seed.sql` & `seed_15_records.py`:** Populates verified synthetic healthcare records across all 5 clinical roles.
- **`audit_schema.py` & `dump_constraints.py`:** Dumps table schemas, foreign keys, and check constraints for automated parity verification.
- **`verify_phase15_sandbox.py`:** Validates RLS policies, trigger boundaries, and negative test cases against the isolated sandbox environment.
- **`scan_secrets.py`:** Verifies zero leaked passwords or private keys in SQL scripts.

## Applying Migrations

```bash
# In carebridge/backend/supabase
python apply_migration.py
```
*Note: Always review pre-execution state and ensure database backups exist in `backups/` prior to applying migrations in production environments.*
