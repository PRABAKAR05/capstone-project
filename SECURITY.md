# Security Policy

**CareBridge AI Security Architecture & Vulnerability Reporting**

The CareBridge AI team takes security and patient data privacy with the utmost seriousness. This document outlines our security architecture, data handling policies, and instructions for reporting vulnerabilities.

## Security Architecture Principles

1. **Row Level Security (RLS) Isolation:**
   Multi-tenancy is enforced at the database kernel level through PostgreSQL Row Level Security. Requests without an authenticated `auth.uid()` or with a mismatched tenant identifier are rejected automatically.
2. **Dual-Context HMAC Administrative Corrections:**
   Administrative updates to critical tables (`carebridge_internal.active_corrections`) require a dual-context authorization protocol combining a secure session context with an HMAC-SHA256 signature generated by an out-of-band DBA key.
3. **Zero-PHI Audit Logging:**
   All API requests, authentication attempts, and authorization checks are recorded in structured JSONL format (`carebridge/backend/logs/audit.jsonl`). Patient names, MRNs, notes, and sensitive credentials are never stored in audit logs.
4. **Cryptographic e-Prescription Verification:**
   All electronic prescriptions are cryptographically signed with HMAC-SHA256 upon issuance. Public verification uses non-invertible cryptographic hashes, exposing zero PII to unauthorized verifiers.
5. **Demographics Masking:**
   Laboratory and support personnel view de-identified patient rosters where direct identifiers are replaced with ephemeral tokens.

## Reporting a Vulnerability

If you discover a security vulnerability in CareBridge AI, please report it responsibly:

- **Do NOT file a public GitHub issue.**
- Send a detailed advisory to the security maintainers at: `security@carebridge-ai.org` (or contact repository administrators directly).
- Include:
  - Description of the vulnerability and attack vector.
  - Step-by-step reproduction instructions or proof-of-concept.
  - Potential impact on clinical data or IoMT telemetry.
- We aim to acknowledge reports within 24 hours and provide a remediation timeline within 72 hours.
